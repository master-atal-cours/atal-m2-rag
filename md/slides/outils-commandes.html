45 s. Cette slide est la troisième du mode d'emploi et présente l'interface et le cycle de travail d'un TP. Tout se passe dans une interface web, lancée une fois pour toutes avec uv run rag sur http://localhost:7860. Suivez le cycle de gauche à droite. On écrit une méthode d'un composant dans rag/*.py, puis on clique sur « Recharger le code », qui recharge les fichiers et reconstruit l'index. L'onglet Index montre le découpage d'un document et ce que la recherche seule ramène, avec les scores, sans appeler le LLM : c'est l'outil pour comprendre une erreur de recherche. L'onglet Chat permet d'essayer, avec la trace et les sources envoyées au LLM, et l'onglet Évaluation mesure sur les 41 questions, chaque réponse à côté de la réponse attendue. La flèche de retour rappelle qu'on corrige le code, puis qu'on recommence. Commentez les remarques du bas. La première indexation demande environ une minute d'embeddings, puis le cache réduit le rechargement à quelques secondes. Une erreur dans le code s'affiche en haut de la page, et l'ancienne version reste active. uv run rag eval lance l'évaluation dans le terminal, et l'option -v affiche les réponses.
