1 min, puis 35 min de TP. Cette slide donne la consigne du TP 4 : router, interroger les données et lire le catalogue. Les quatre étapes numérotées se suivent dans cet ordre. D'abord le routeur, avec les quatre routes de Route et la sortie structurée, puis le catalogue, avec la liste des documents dans le prompt. Ensuite l'outil SQL (tables, schéma, SQL, exécution, une correction, sinon None), et enfin build_direct dans prompt pour la route conversation, avant d'évaluer. Le routeur, le catalogue et la route conversation sont rapides à écrire ; le text-to-SQL est le gros morceau. Conseillez d'écrire le SQL d'abord sans la correction, de le tester sur deux ou trois questions d'agrégation, puis d'ajouter la robustesse. Le bloc de code rappelle les outils fournis : self.tables (un TableStore) avec search, schema et query. Pour tester, la trace de l'onglet Chat montre la route, la requête réécrite et le SQL ; c'est aussi l'interface de la démonstration finale. Pour ceux qui ont fini, deux pistes : un agent avec llm.run_tools, ou des questions nouvelles dans data/questions.toml, avec leur réponse de référence. C'est le meilleur test de robustesse, et une bonne introduction au surapprentissage d'un jeu d'évaluation. Les étudiants bloqués repartent de solutions/phase-3.zip, et la solution complète est phase-4.zip.
