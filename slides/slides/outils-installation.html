git clone \

cd atal-m2-rag && uv sync

dans data/corpus/, depuis les sources officielles

3 · Servir le LLM · Ollama

uv run python scripts/setup_ollama.py

modèles téléchargés et essayés · sans GPU : --model qwen3.5:4b

serveur de l'université ? son adresse dans config.local.toml

4 · Vérifier

Ensuite, uv run rag ouvre l'interface sur http://localhost:7860. config.local.toml n'est pas suivi par git.

45 s. Cette slide est la deuxième du mode d'emploi et détaille l'installation en quatre étapes. L'étape 1 installe le projet : git clone du dépôt, puis cd atal-m2-rag && uv sync. Sans uv, python -m venv .venv puis pip install -e . fonctionnent aussi. L'étape 2 télécharge le corpus avec uv run python scripts/download_corpus.py, qui doit afficher 48/48 fichiers disponibles (10 Mo) dans data/corpus/. Idéalement, les étudiants ont lancé les étapes 1 et 2 pendant l'introduction. L'étape 3 sert le LLM et dépend de chacun. Avec Ollama, scripts/setup_ollama.py vérifie l'installation (sinon il affiche la commande), lance le serveur, télécharge les deux modèles et les essaie, et OLLAMA.md détaille les problèmes courants. Sans GPU, un modèle de 9 milliards de paramètres sera lent : l'option --model qwen3.5:4b télécharge un modèle plus petit et l'indique dans config.local.toml. Avec un serveur de l'université, on met son adresse dans config.local.toml plutôt que dans config.toml, car ce fichier n'est pas suivi par git et les solutions ne le remplacent pas. L'étape 4 vérifie avec uv run rag check, qui doit afficher deux coches, une pour le LLM et une pour les embeddings en dimension 1024. S'il en manque une, c'est presque toujours l'adresse ou le nom du modèle. Ensuite, uv run rag ouvre l'interface sur http://localhost:7860, à garder ouverte pendant toute la séance, et les sorties affichées sont réelles.
